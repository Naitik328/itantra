# Bengali TTS — ready-made Piper voice (no fine-tuning)

For iTantra's offline TTS: `bn_BD-google-medium`, a Piper voice, patched
with `sid=12` fixed as the single female speaker to use. No training was
done for this deliverable -- the model was already on disk locally, patched
with sherpa-onnx metadata, and shipped as-is (same shortcut as
`../englishfinal/`, adapted for a multi-speaker source model).

## Why not fine-tune

`ai4bharat/Rasa` (config Bengali) was analyzed before committing to a plan
(28,086 train rows, ~16.4GB parquet, genuine `gender` column). Two things
came out of that analysis:

1. **Gender order is reversed from Telugu**: Male rows come first
   (roughly 0-14,000), Female after (~14,500 onward) -- confirmed by
   sampling `gender` and the `BEN_M_.../BEN_F_...` filename prefix across
   the split via HF's datasets-server, the same way Telugu's order was
   confirmed.
2. **The same quote-character bug that cost seven CUDA OOM crashes on
   Telugu is present here too.** Sampling 260 rows spread across the whole
   split found a row with a literal `"` character (0.4% of the sample --
   Telugu's actual rate over its full 12,612 rows was 1.8%, so this is a
   consistent, expected proportion, not a fluke). See
   `../telegufinal/README.md` for the full story: piper1-gpl reads
   `metadata.csv` with Python's `csv.reader(delimiter="|")`, whose default
   dialect treats `"` as a quote character, so an unbalanced quote silently
   merges dozens of unrelated rows into one multi-thousand-character "row"
   and blows self-attention memory past the GPU's capacity.

Given a fine-tune here would need the exact same preemptive fix Telugu
needed (already proven out, not a new risk), the team's call was to use the
ready-made voice instead for Bengali specifically, to avoid another
multi-crash training cycle, and revisit fine-tuning here later if quality
needs improving.

## The voice: bn_BD-google-medium, speaker 12

- Source: local file already on this machine (`bn_BD-google-medium.onnx`),
  originally from Piper's `bn_BD-google-medium` community voice (dataset
  credit: `google`, per its `.onnx.json`) -- **license/provenance was not
  re-verified for this session; confirm before shipping if that matters for
  iTantra's use case.**
- **16 speakers** (`n_speakers=16`) -- unlike every other language in this
  repo, this is NOT a single-speaker model. The caller must always pass
  `sid=12`.
- 22,050 Hz, medium quality, VITS architecture (same family as the other
  languages' models)

### How speaker 12 was picked

All 16 speaker IDs were synthesized with the same Bengali sentence and
checked by median pitch (F0):

| sid | median F0 | verdict |
|---|---|---|
| 0 | 141.0 Hz | male |
| 1 | 165.0 Hz | female (borderline) |
| 2 | 155.5 Hz | male |
| 3 | 178.3 Hz | female |
| 4 | 149.3 Hz | male |
| 5 | 159.0 Hz | male |
| 6 | 151.5 Hz | male |
| 7 | 168.9 Hz | female (borderline) |
| 8 | 144.1 Hz | male |
| 9 | 155.5 Hz | male |
| 10 | 162.2 Hz | male |
| 11 | 198.1 Hz | female |
| **12** | **257.6 Hz** | **female -- clearest, picked** |
| 13 | 181.8 Hz | female |
| 14 | 154.3 Hz | male |
| 15 | 243.9 Hz | female (close second) |

sid=12 and sid=15 were both generated as longer samples and listened to;
sid=12 was clearer and was picked. Re-verified on the final
metadata-patched, graph-optimized `.onnx` via `sherpa_onnx.OfflineTts`
(the real Android code path, not just `piper.PiperVoice`): median F0
257.0 Hz, RTF 0.054.

## CRITICAL integration note: this is a multi-speaker model

Every other language in this repo (`hindifinal/`, `englishfinal/`,
`telegufinal/`) ships a single-speaker model where `sid=0` is the only
valid, correct choice. **This one is different.** `bn_BD-google-medium` has
16 speakers; `sid=0` is male. The Android integration must pass `sid=12` on
every `generate()`/synthesize call for Bengali specifically -- there is no
way to bake a default speaker into the ONNX file itself. Flag this loudly
to whoever wires up the sherpa-onnx call per language (see
`../INTEGRATION.md`), since a silent copy-paste of another language's
`sid=0` call would produce a male voice with no error.

## Latency and speaking rate

Same story as every other language here -- see
[`../INTEGRATION.md`](../INTEGRATION.md). `numThreads=4` (not sherpa-onnx's
default of 1), build `OfflineTts` once and reuse it, `lengthScale=0.85` for
natural speaking rate (cannot be baked into the ONNX metadata). Do not
int8-quantize (`benchmark_results.csv`).
