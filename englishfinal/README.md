# English TTS — ready-made Piper voice (no fine-tuning)

For iTantra's offline TTS: `en_US-hfc_female-medium`, a Piper voice that
ships pre-trained. No training is done for this deliverable — the model is
downloaded, patched with sherpa-onnx metadata, and shipped as-is.

## Why not fine-tune (the earlier plan)

The original plan was to fine-tune Piper on `SPRINGLab/IndicTTS-English` for
an Indian-accented voice, mirroring the Hindi pipeline. That ran into a real
bug: the dataset turned out not to be single-speaker (see "Gender-filtering
bug" below), so the first trained model randomly switched between male- and
female-sounding output.

The team's decision: for English, use a ready-made single-speaker Piper
voice instead of fixing and re-running the fine-tune. Zero training cost,
zero risk of repeating the bug, and Piper's official voices are
well-tested. Hindi remains fine-tuned on Indian-accented data since that
pipeline is clean and already shipped.

## The voice: en_US-hfc_female-medium

- Source: official Piper voice, from `rhasspy/piper-voices` on HuggingFace
  (`en/en_US/hfc_female/medium/`)
- Single speaker, confirmed female (median F0 209 Hz on a generated sample —
  female range is roughly 165-265 Hz, male roughly 85-155 Hz)
- American English accent (`en-us` espeak voice)
- 22,050 Hz, medium quality, same VITS architecture as the Hindi voice

## Files in this folder

| File | What it is |
|---|---|
| `en_US-hfc_female-medium.onnx` | the model — downloaded from Piper, then patched with sherpa-onnx metadata (`7_add_sherpa_metadata.py`) and graph-optimized (`8_optimize_onnx.py`) |
| `en_US-hfc_female-medium.onnx.json` | Piper config (sample rate, phoneme map) — downloaded as-is |
| `en_US-hfc_female-medium.tokens.txt` | generated by `7_add_sherpa_metadata.py`; 159 tokens, 0 multi-character symbols (this voice's phoneme set didn't need any dropped) |
| `test_sample.wav` | sample output, generated via `sherpa_onnx.OfflineTts` (the real Android code path), `num_threads=4`, `length_scale=0.85` |
| `try_it_yourself.py` | interactive test — type English text, hear it |

## Setup steps actually run for this voice

```bash
# 1. Download from HuggingFace (see URL above)
# 2. Patch sherpa-onnx metadata + generate tokens.txt
python 7_add_sherpa_metadata.py --onnx en_US-hfc_female-medium.onnx \
    --config en_US-hfc_female-medium.onnx.json --language English
# 3. Graph-optimize (small win, ~7%, safe/portable — ORT_ENABLE_EXTENDED not ORT_ENABLE_ALL)
python 8_optimize_onnx.py en_US-hfc_female-medium.onnx
# 4. Verify with the real engine
python try_it_yourself.py
```

Step 2 is **mandatory** for any Piper voice used with sherpa-onnx, downloaded
or fine-tuned alike — a plain Piper export has no `metadata_props`, and
sherpa-onnx's native init crashes with `'sample_rate' does not exist in the
metadata'` without it.

## Latency and speaking rate

Both are set on the *caller* side, not in the model file — see
[`../INTEGRATION.md`](../INTEGRATION.md). Short version: `numThreads=4` is 3x
faster than sherpa-onnx's default of 1, the `OfflineTts` object must be built
once and reused (model load is ~1.5 s), and speaking rate comes from
`lengthScale` (0.85 ≈ natural rate), which **cannot** be baked into the ONNX
metadata — sherpa-onnx ignores it there. Do not int8-quantize: measured 3x
*slower* on this project.

## Gender-filtering bug found during the fine-tune attempt (kept for the record)

`SPRINGLab/IndicTTS-English` has no `gender` column in its schema, and a
derived repo `Anjan9320/IndicTTS-English-female` exists — from which it was
originally concluded that the dataset is genuinely single-speaker female and
needs no filtering. **That conclusion was wrong.** The dataset is laid out
exactly like `IndicTTS-Hindi`: a contiguous female block followed by a
contiguous male block. It was caught by listening to the trained model and
confirmed by measuring median pitch (F0) directly from the source audio with
`2_detect_gender_by_pitch.py`:

| index range | median F0 | speaker |
|---|---|---|
| 0 – 8400 | 193–265 Hz | female (no exceptions across 43 sampled clips) |
| **8510** | **202 Hz** | **female — last confirmed** |
| 8520 | 156 Hz | ambiguous |
| 8530 onward | 97–189 Hz | male |

**Lesson for Bengali and Telugu:** do not trust a dataset's metadata, or its
absence, to tell you the speaker is uniform. Run `2_detect_gender_by_pitch.py`
over the downloaded audio before training — it reads the wavs directly and
works regardless of what the dataset does or doesn't label.

## Unused pipeline scripts (kept for reference, not run for this voice)

`1_download_dataset.py`, `3_filter_female_only.py`, `4_filter_duration.py`,
`5_train.sh`, `6_export_onnx.py` were built for the abandoned fine-tune on
`IndicTTS-English` (filtered to the 8,510-clip female block, `en_data/` on
the network volume). They're left in place in case English fine-tuning is
revisited later — they are not part of producing the current voice.
`2_detect_gender_by_pitch.py` and `7_add_sherpa_metadata.py`/
`8_optimize_onnx.py` are the ones actually used, and the pitch-detection
script in particular is worth reusing for Bengali/Telugu.
